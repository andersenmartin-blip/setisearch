# Fixed two-background sensitivity

This final posthoc check compares exactly two background estimates for V2E2-0235: the negative-side median and positive-side median, using the original true-trace distances9–12 pixels. Each estimate uses exactly three pixels per row. Both original side medians remain contextual measurements, so one-sided selection cannot produce an empty-mask median.

The runner reads only the hash-bound, already measured `analysis/results/SELECTED_NATIVE_PIXELS.npz`:331 rows×25 pixels. It reuses the saved row/column maps and the same232 training rows, rebuilding one pooled signed template per estimator. Target and all eight held-out windows retain eleven rows each. All18 outcomes and198 row records are kept, including explicit blocked outcomes. Raw/model/residual arrays, true-coordinate maps, fit and background masks, and native row/chip maps are saved separately by estimator/window.

Training normalization, signed template samples, perrow evaluated-template normalization, fixed-background signed OLS amplitude, and every original window residual metric remain unchanged. The window aggregation function is copied from the pinned original method with only an explicit estimator argument added. The original pooled two-sided results are comparison metadata and are never rewritten. Each estimator reports all eight controls, including on/off per-pixel mean absolute residuals.

This tests background-estimator sensitivity. It neither assigns FP contamination nor changes U. The positive side lies closer to the FP fiber trace, but that fact does not establish its flux contribution. No estimator is chosen as preferred from these outcomes.

Execution requires `python run_sensitivity.py --execute --release ROOT_RELEASE.json`. Without `--execute` no observational calculation occurs.
