## Registered source and root contracts

The original fixture and fixed launcher bind the plan to the actual original
repository root before spending. Copied workers receive a separate explicit
`invocation_repository_root` in the inherited, byte-authenticated admission
bundle. Builders require an independent caller root; they never infer it from
scope or silently accept the plan's own root as their trust anchor. The c
spender's exact namespace, ledger directory and marker policy reject both a/b
namespaces, paths and spent commits. Activation also requires a caller-supplied
activation commit and rejects historical commits before its own filesystem IO.
In the supported launcher path that argument comes from its raw-pinned public
readback input; a local JSON provenance label alone supplies no public authority.

The registered historical adapter executes only held, independently pinned
copies of the archived b spender and shared storage implementation. Its nine
mandatory historical source/JSON inputs are copied at their exact relative
paths, separately frozen as inputs, and checked against fixed raw pins. They
include the b receipt/witness, the public 107-file manifest, and the retained
scope/journal manifests and observations. Those input literals and original
root are policy, never automatically refreshed from candidate files.

Every joined observation authenticates the live historical scope and b journal,
plus the c ledger. c is measured on both sides of the historical read, with a
held canonical before value. Missing history, source substitution, scope/root
changes and storage mutations refuse the gate. The original b source and spend
record are preserved; the c module does not authenticate b in their place.

scope. It validates totals, metadata, ancestry, raw historical pins, path overlap
and device/inode aliases. Current and external inventories are detached before
allocation, and each historical/current journal row is charged once. The eight

so the strict finalizer can apply the same complete allocation before and after
