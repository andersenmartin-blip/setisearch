# Finite supervisor/guard engineering preparation

This prospective allocation permits only compiling the attached Linux leaf
guard and running harmless standard-library fake children to test its process
controls and evidence collection. It is preparation, not runtime-materialization
or scientific admission. No wheel, scientific package, HDF5/telescope input or
credential is read or imported.

Each complete compiler/engineering-test attempt has its own 30-second wall
ceiling and 512-MiB address-space ceiling. Compiler source, compiler binary and
all reported header dependencies are SHA-256 pinned in preparation evidence;
produced native guard/seal binaries must be pinned again by the prospective
runtime freeze. Individual fake children use smaller budgets. No network,
dependency installation or fallback compiler is eligible. Compiler operations
use their own sessions with group termination on deadline; no full compiler
provider custody certificate is issued.

The original engineering attempt failed before Python handoff because ptrace
was refused. Its source, compiled binary, compiler/header pins, spent allocation
and failure result are retained in `engineering-attempt1`. Raw compiler streams
were empty and recorded; the first test harness removed fake-child temporary
raw streams after recording their byte counts/hashes. That missing raw custody
is not reconstructed. No ptrace retry is admitted.

A distinct corrected engineering attempt 2 is prospectively allocated 30
seconds / 512 MiB for the cooperative two-phase guard. Phase 1 denies
descendants/network/async IO before the fixed pinned-Python descriptor handoff;
a frozen stdlib ctypes bootstrap then installs an exec-denying second filter
before pip or native scientific imports. Phase 2 emits an activation marker
in retained stderr. Corrected test receipts and raw streams are retained.
This is a corrected preparation implementation, not runtime-scope activation.

A distinct engineering attempt 3 is prospectively allocated 30 seconds /

Attempt 2 remains preserved; this is a new engineering check, never a runtime

The pre-correction candidate sources/binaries are preserved under attempt 4.

Leaf runtime budgets remain separately prospective: root 300 seconds, active
270 seconds, finalization 30 seconds; pip and collector each at most 120 seconds
and the remaining global interval, 512-MiB child address space, 100 CPU seconds,
128-MiB per regular file, 2-MiB per output stream, 512-MiB opaque read reserve

artifact reserve. All keys, including sampling interval and cleanup reserve,
must be explicitly frozen/passed; unknown or missing keys are refused.

IO/storage/output gates are sampled. A crossing fails closed and observed raw
output before termination is retained even when it demonstrates an overshoot.
Neither these observations nor the address-space limit certify lifetime peak

differ, proc IO is explicitly unavailable; exact wait4 direct-child exit and
ru_maxrss remain engineering observations. Missing counters never become zeros.
