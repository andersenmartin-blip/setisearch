The documented route is **GET `https://archive.eso.org/hdr?DpId=<exact URL-encoded ADP identifier>`**, without `.fits`. ESO’s [programmatic demo](https://archive.eso.org/programmatic/) exposes this separately from spectrum download. Its URL-only action was tested with the official demo ID: HTTP 200, `text/plain`, returning the `/hdr` URL. No actual product header or target spectrum was requested.

The concrete URL is established; the header endpoint’s current rendering is not yet validated. Accept only bounded FITS-card plaintext or FITS text inside HTML `PRE`, then identify the primary `SIMPLE`–`END` block. Reject other formats, incomplete primary blocks, conflicting keys, or product mismatch. The demo supports both raw and product IDs: an **ADP ID must remain an ADP product request**, checked by `ARCFILE`. Do not substitute a raw-frame header. ESO’s [1D format description](https://archive.eso.org/cms/eso-data/help/1dspectra.html) places product metadata in the primary header and science arrays in the binary-table extension; the viewer’s exact HDU selection is not promised by that document.

Use recorded `HIERARCH ESO DRS BERV`, preserving its sign, and verify `OBJECT`, `INSTRUME`, position, `DATE-OBS`/`MJD-OBS`, exposure time, `NCOMBINE=1`, `SPECSYS`, and a unique HARPS raw progenitor from `PROVn`. `BERVMX` is a different quantity and is not a substitute. [Phase 3 documentation](https://archive.eso.org/wdb/help/adp/phase3_help.html) identifies `ARCFILE` as the dataset identity and warns that the ADP timestamp is archival, so chronology must use the observation metadata.

The proposed acquisition groups each target by calendar month **number 1–12 across all years**, choosing the latest eligible observation for each month number (ties: lexicographically smallest ADP ID), with at most 12 products per target and 24 total. Exact month choice, IDs, metadata hashes, and code must be frozen before any header fetch. Bounds: one attempt per product, 30 seconds, 512 KiB per response, 12 MiB total, no retries or redirects. These are project bounds, not an ESO service guarantee. The size allowance was increased before any target request because a saved primary header alone produced 250,533 bytes of newline-card text. First selected product is the format/identity canary; an unexpected canary stops the batch. Oversized or missing headers remain failures; no whole-spectrum fallback is implicit.

A separate, unqueried official lead is the [HARPS RV Catalog DR1 schema](https://www.eso.org/qi/catalog/show/416): it documents `adp_dpid`, `raw_dpid`, observation times, exposure time, and `drs_berv` in km/s. Its stated coverage is 2003-09-19 through 2023-05-30 (289,843 rows, 6,488 objects). This catalogue is not queried or substituted in the current plan.

`SOURCES.json` records official sources retrieved 2026-11-02; `CONTRACT.json` separates verified URL facts from pending runtime checks. `LOCAL_PARSER_EVIDENCE.json` hashes the existing local FITS parser. No original science code or prior results were changed.

The prepared implementation now requires `SPEC_RES=115000` and recorded `ESO INS HEFS ST=F` for automatic extreme selection; `T` indicates EGGS, and missing/unknown state remains pending. It retains the actual instrument mode (which can be `HARPS+NIRPS`), processing fields, and original relevant card comments. Inherited `abs(BERV) <= 100 km/s` and complete single-raw provenance checks reject implausible or ambiguous records. Local validation covers the actual saved primary plus targeted failure boundaries without new headers or arrays.
