This directory prepares the bounded HARPS BERV header batch. It cannot request a header without an exact `PLAN.json` and matching root-written `ROOT_RELEASE.json`. The failed original metadata query is not an input; the factory requires both explicitly supplied metadata requests to be complete.

`make_plan.py` selects the latest eligible observation per calendar month number 1–12 across all years, separately for HD122640 and HD135204; equal-time ties use the lexicographically smallest ADP ID. Execution order is target order as written, then month number. Exact IDs, URLs, metadata inputs, old-BERV coverage, and code hashes are frozen in the resulting plan. At most 24 headers, 12 per target, one attempt each, 30 seconds, 512 KiB per response, and 12 MiB total; no redirects/retries or whole-spectrum fallback.

`fetch_headers.py` accepts only FITS-card plaintext or HTML PRE rendering. It parses the primary SIMPLE–END block and preserves exact response bytes and receipts. The first planned product is a canary: request, identity, BERV, or compatibility failure stops the remaining batch. Any later unrecognized format also stops the batch. Reaching a byte cap is an incomplete response, never a silently truncated success. Target requests require a matching `approved: true`, `plan_sha256`, and `code_hashes` in ROOT_RELEASE.

Identity checks require exact ADP ARCFILE, target, HARPS instrument, matching times/exposure/coordinates, NCOMBINE1, BARYCENT, SPEC_RES115000, and exactly one complete expected raw-provenance value. BERV must be finite and within the inherited absolute100km/s sanity limit. HEFS STtrue excludes EGGS; false admits the high-resolution mode despite possible INS MODEtext HARPS+NIRPS; missing/nonboolean mode remains pending. Full primary response and original relevant card comments are retained. Extension table wavelength/flux units and air-frame representation remain provisional until payload headers are verified before array access.

`select_extremes.py` proposes minimum then maximum verified BERV per target, in HD122640/HD135204 order; equal-BERV ties choose the lexicographically smallest ADP ID, and identical selections are deduplicated. It reports partial header coverage and binds each selected row to its planned job and header bytes/receipt. Existing coverage comes exclusively from BERV_COVERAGE.csv rows scope=all_existing300. A target gets no payload proposal unless its combined existing+passing-new span is strictly greater than c/R=2.6068909391304347km/s. This is a descriptive planning displacement benchmark, not statistical power or a physical-origin classifier. No payload download is authorized by this proposal.

`validate_local.py` reads only the primary FITS blocks of an existing saved product and exercises relevant parser, identity, provenance, month-selection, and byte-cap boundaries offline. Its current result is `LOCAL_VALIDATION.json`. A separate independent reviewer examines the final code and exact plan before release. No original science code or earlier survey results are edited.
