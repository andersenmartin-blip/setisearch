The reviewed F sources support the proposed single harmless kernel-IO control.
No actual control, installed interpreter, scientific import, old-scope rerun,
guard recompilation, or frozen C/D/E edit was performed in this review.
Activation remains owned by root after immutable publication and full readback.
No actual F dispatch has occurred at the review boundary.

## Observer and supervisor

The resolver binds the parent's proc-visible PID to the first `NSpid` element
and its actual local PID to the last. It retains and rechecks the proc root,
owner directory, owner UID, PID/Tgid, namespace inode, starttime and named
identity. Candidate identity requires the exact local child PID, namespace
depth/inode, proc-visible direct parent, single-thread Tgid, UID, and stable
child starttime/held directory. Unknown namespace, orphan, reused identity,
alias and ambiguous candidate fixtures refuse. A live S/R/Z scheduling change
alone does not change process identity.

The parent task children route and finite fallback scan charge rejected
candidates, explicit bytes, entries, and observer operations. Bound descriptors
are closed even when the observer budget refuses another accounting operation;
closed state prevents a second close of a reused numeric FD. The selected
caller retains its proc-root handle and closes child, owner and root handles.

Terminal observation requests `WEXITED|WNOHANG|WNOWAIT` for the exact waitable
child, requires terminal wait ownership and zombie state, and reads retained
IO before the supervisor's exact `wait4`. Missing counters remain missing;
they are never replaced by zero. The F supervisor retains the original held
binary pins and two-phase guard, parent-death controls and no-descendant policy.

One inherited cleanup issue was fixed solely in the new F copy: repeated
selector failure could previously interrupt cleanup before reaping. F now
keeps bounded terminal polling and exact `wait4` independent of stream drain
or selector failures. The repeated-selector-failure fixture retains failure
status, reports unavailable guard authentication honestly, and still reaps.
Its earlier fixture assertion failure is retained in the draft's failure log.

## Root control gate and launcher

The control uses base Python `-I -B -S`, a fixed 131,072-byte ASCII payload,
eight full hash-checked passes, and exactly 1,048,576 explicit workload bytes.
The gate binds the retained report to the same local/outer PID, starttime and
held directory as the observed and reaped child. It requires all seven exact
false authority fields, isolated/no-site/bytecode flags, the frozen base
executable, exact payload geometry/pass hashes and all seven unsigned kernel
IO fields. Kernel terminal `rchar` must cover the known workload and the child's
self-observed postwork count. A genuine storage-layer `read_bytes` value of zero
is acceptable for page-cache reads and is not a substituted missing counter.

The derivative builder's accidental numeric substring replacements were
corrected before freeze. The reviewed declarations now match the allocation:
30-second gate lifetime, 20-second active cutoff, 10-second child wall,
5-second child CPU, 2-second child cleanup; 256 MiB parent AS and 128 MiB child
AS; 16 MiB stored artifacts with 1 MiB terminal reserve; 1 MiB output file cap;
64 KiB leaf stdout/stderr each. Parent explicit read allocation is
448+32+16+16 = 512 MiB; the separate opaque 16 MiB child reserve gives a
528 MiB conservative joined reservation. Inputs are capped at 128 MiB.

The launcher authenticates its fixed gate/Python inputs, refuses an occupied
one-shot root, dispatches once, observes the gate with WNOWAIT and records exact
wait4 lifetime/RSS. Failed exit/status or missing child peak cannot produce
caller success. Its administrative verification/storage work remains outside
the gate allocation and is explicitly labelled. Whole-parent result
serialization is covered by the launcher's external lifetime observation.

## Claim boundary

F can supply authentic selected kernel counter and namespace-binding evidence
for this deterministic control. It does not supply per-file attribution,
complete loader history, complete native IO, simultaneous process-tree RSS,
transient storage peaks, hosted transport qualification or a scientific/runtime
certificate. The protocol retains these limitations and the maintained
production gates remain pending. The historical eleven labels belong to an
inert diagnostic constructor; they are not fields to fill to activate science.
C/D/E stay closed, and F has no retry or automatic successor.

Primary kernel source corroborates unsigned IO output in
[fs/proc/base.c](https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux/%2B/master/fs/proc/base.c).
The scope's actual future observations, rather than documentation or these
