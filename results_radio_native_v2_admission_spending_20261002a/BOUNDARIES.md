# Admission and spending preparation boundary

This package changes only prospective engineering admission. The previous failed
activation marker and invocation remain permanently spent. The prospective
`20261002b` marker is an interface identity only; this package creates no such
marker and invokes no protected control.

The source guard obtains its receipt and spend witness from the exact admission
bundle whose SHA256 is independently retained in actual child argv. It checks
actual argv/environment, source bytes, scope, runtime custody and the durable
record before source or identity writes. A receipt dictionary or a self-asserted
public-readback boolean is not independent evidence. Synthetic positive tests
execute only the production guard prefix followed by a tiny stdout sentinel;
no 26 MiB generator is present in those test recipes.

A future outer invocation must claim the marker once in a pre-existing private
0700 ledger fixed by the original repository path in its exact current plan.
There is no CLI ledger override or incoming-witness bypass in `run_control`.
The record key excludes scope and activation commit, so neither changing the
scope nor republishing the same marker permits another invocation. O_EXCL,
file/directory fsync and stable readback precede the first scope creation. Any
subsequent failure leaves the marker spent; there is no remove/rearm helper.

Worker witness checks do not claim again or call Git. Authentication is relative
to the trusted outer argv/bundle chain and the private local filesystem. This
is not a standalone signature or a guarantee against same-owner/privileged
ledger deletion, filesystem rollback, copying or post-check mutation. The
record and directory identities are local observations, not portable identities.

The persistent ledger is intentionally outside the disposable invocation scope.
Its record has a 16 KiB bound, but its allocated storage is not yet joined into
the current whole-scope resource account. Complete resource/lifetime/transport
qualification remains false, and the production ledger is not initialized by
these preparation tests. New public execution evidence, a distinct activation
and the remaining gates are required before any future control. A successful
engineering control would still not admit native/scientific telescope analysis.
