# Scope-bound six-header cache qualification

The four original BLC66 drafts were reconstructed byte for byte from tool
history. `DRAFT_RECONSTRUCTION_RECEIPT.json` identifies those inert historical
drafts. They were never imported or executed. `qualify_generic_once.py` is a
separate worker, with scope schema
`SETI_VISIT2019_SIX_HEADER_CACHE_QUALIFICATION_SCOPE_V2`.

The generic worker accepts the exact manifest path, SHA256 and manifest schema
in its public frozen scope. It binds the actual last complete typed planner's
worker, parser, scope, result and execution receipt separately from the shared
inert `cache_admission.py` source. There is no fixed prior BLC node, visit,
prefix size or initial BODY count in these generic source-identity gates.
The scientific ON target remains HIP98505.

`cache_admission.py` exposes `admit_cache_history(scope, admitted)` and does
not import a parser, h5py, networking code or source-value libraries. Its input
is `scope.cache_admission`, with schema
`SETI_VISIT2019_GENERIC_METADATA_CACHE_ADMISSION_V1`. The caller installs
resource limits before invoking it. It returns six ordered dictionaries
containing source identity, logical file size, strong ETag and unchanged
`cache_ranges` triples `(absolute_offset, retained_bytes, exact_file_pin)`.
Each loaded file is admitted by canonical path, byte length and SHA256.

The initial transport entry pins the actual scope, wrapper, global result,
execution receipt and root admission. Its expected schema/status fields
select the supported opaque prefix-transport contract. The initial scope's
actual `prefix_bytes` determines every range, retained length and six-source
BODY charge. Every source's HEAD must have exact URL, status 200, positive
logical length, strong ETag and no content encoding. Every prefix GET must
have exact URL, status 206, matching ETag, exact Content-Range/Length,
identity encoding and matching saved binary SHA256. Separate HEAD, PREFIX
and HEADER receipts must equal the embedded global result records. Actual
complete status, resource closure, zero retries/redirects and no source-value
API are required. It never repeats a HEAD or GET.

The exact launcher source and its actual outer process-resource receipt are
also pinned. The latter must bind the original scope, worker, root admission,
inner execution and result byte pins, with reaped child exit zero, no signal
or timeout and affirmative measured CPU, wall and RSS caps. Inner resource
claims alone do not admit a captured prefix.

Optional completion history is finite and supports only the explicit typed
fragment transport contract. Each completion must bind its closed transport
and prior actual typed planner scope/result/execution. The parent's cache
configuration must equal the exact previous history. The immutable initial
V2 planner instead uses its existing source-id manifest, initial scope,
initial execution, initial result and six prefix pins as an exact initial-only
anchor. The loader explicitly adapts those original fields without changing
the frozen planner or inventing aliases. Later round scopes require the
generic cache configuration directly. Planner input pins may be inline or
carried by an authenticated `SETI_VISIT2019_TYPED_STRUCTURE_INPUT_PINS_V1`
manifest. A proposed range must
be an exact missing-fragment object from that parent plan, with typed-parent
evidence and `payload_pointer: false`. Its source, strong ETag, logical size,
range, length, saved receipt and retained SHA must all agree. New ranges may
not overlap any already retained byte, including an earlier request in the
same round. Unsupported completion schemas fail closed. No h5py read miss
can supply a proposal to this helper.

A source retaining missing fragments after an invalid or unsupported parse
cannot authorize them. The whole six-source parent must be clean and have
overall status `INCOMPLETE_TYPED_METADATA_FRAGMENTS`. Every source has empty
invalid/unsupported lists; every requested source has that incomplete status.
The fixed request list equals the entire clean typed missing-fragment list.

The separate `metadata_with_types.py` core reads only bounded header attributes, shape,
datatype, chunk shape and creation-filter metadata. Its cache-only logical
reader reports a miss without filling gaps or authorizing acquisition. The
already verified version-3 data-layout message exposes the chunk-index root
pointer with byte evidence, without traversing a node. Six actual geometry,
frequency/time grid, name, pointing and timestamp checks follow the fixed
method described in the historical draft. The one-arcminute pointing gate
tests distinct header pointings; it does not certify a telescope beam model,
blank sky or independent noise. The original metadata core remains unchanged.
The additional core records each attribute's shape, NumPy datatype string
and kind, and bounded encoded HDF5 datatype bytes with length and SHA256.
`root_attribute_types` and `data_attribute_types` form exact key bijections
with the corresponding plain value maps, allowing later compact metadata
copies to preserve original datatypes. Encoding a datatype reads metadata;
it does not read dataset values or invoke a signal codec.

Each qualified source also carries the exact previously admitted typed-plan
superblock and cached layout-pointer evidence for a separately scoped pure
chunk-index planner. This qualification does not traverse that index.

The future first native ordinal is fixed from common metadata as
`floor(n_native_frequency_chunks/2)` before amplitudes. This worker scores
zero hypotheses. Metadata eligibility grants neither source-value acquisition
nor independent validation: those remain blocked within this phase. A future
root scope may admit a separately bounded exploratory frame after checking
the known closed protections; this phase makes no universal registry claim.

Production CPU, wall, address-space and output caps remain 20 seconds,
300 seconds, 512 MiB and 4 MiB within the 12 GiB shared workspace cap. The
sole h5py import occurs after source/provenance admission and installed
limits. Output is create-only and all inputs receive exact end readbacks.
The root process separately measures the complete child closure. Root owns
the sole production run and the sole 12-case pure synthetic fixture run after
independent source review; no such run is part of author preparation.
