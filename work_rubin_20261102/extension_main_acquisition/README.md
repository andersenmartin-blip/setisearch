## Integrity checkpoint and transfer limits

Acquisition requires a new `ROOT_RELEASE.json` in this directory, written only after root publishes the exact selection, plan, scripts and unchanged scientific method and verifies their remote bytes. The original study's release is not reused. Before any request, the acquisition script validates the selection, request coverage and matching release hashes. This is an internal integrity checkpoint under the existing user authorization.

The code, endpoints and requested source/forced fields are the same as the original acquisition: no more than two workers, two attempts per original request, 40-second request timeout, 20 MB per response and 80 MB charged response bytes across the extension. Failed/incomplete attempts are retained and conservatively charged; there is no replacement target or alternative service. Cost remains 0 DKK. Exact 64-bit identities are decimal strings, and an out-of-selection or floating-point identity is rejected.

## Fixed analysis and complete reporting

`acquire_main.py` is byte-identical to the original acquisition script. `run_main.py` changes only the output directory and the summary key that previously named the fixed count 188. It loads the unchanged `method_review/detector.py` and `CONFIG.json` through the original method hash checks. Source-position science flux and object-position forced science flux remain separate; uncertainty, quality and missing-withdrawal limitations remain explicit. The wrapper reports every selected object once per stream and retains every October measurement, baseline failure, numerical result and trigger.

Outputs are written only to `../extension_main_analysis/`. The original numerical and selection files are preserved. Numeric evaluability and fully resolved quality are separate conditions; reaching a numerical count of 50 does not remove unknown withdrawal information or create an image-validated null result. The extension's selection is conditional on metadata cadence/quality and Gaia criteria, so it is not an unbiased sample of all stars in the field.

`acquire_trigger_cutouts.py` changes only its input/output directories. After fixed analysis it preserves all triggers and freezes an exact-source cutout queue: all unique associated source identities if there are at most 30, otherwise the first 30 by frozen selection index, time and exact source ID. Forced triggers require an exact object/visit/detector/band source counterpart; there is no nearest-source substitution. Science/template/difference products, including available uncertainty and mask planes, are retained. Zero triggers produce an explicit zero-request record. Image availability alone does not establish a physical origin.

An independent reviewer compares the extension scripts against the original wrappers before release, then independently reproduces the extension numerical outputs after acquisition. No threshold, baseline, quality or duplicate rule is tuned on extension flux. All necessary changes in scientific rules would require a separate prospective study.
