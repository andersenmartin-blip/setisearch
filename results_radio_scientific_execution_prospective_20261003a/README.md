`scientific_admission.py` validates eleven complete raw documents against mandatory independently retained raw pins, preserved scientific identities, complete executable inventory, ELF/plugin dependency graph, runtime identity and immutable publication anchors. It rejects candidate codec certificates, prospective freezes, offline mock transport and incomplete or failed scientific outcomes. A genuine, complete `public-scientific-evidence` package can pass. Positive test packages belong to `synthetic-test-fixture` and remain scientifically inadmissible; the separate production-schema smoke test uses explicit simulated anchors only in memory.

The immutable chain is:

| Publication | Documents and binding |
|---|---|
| Basis | Preserved metadata, source codec/receiver certificate, actual hosted-native transport certificate, fixed protocol and exact limits |
| Freeze | Complete scientific code/input/runtime closure, binding the original source metadata and the basis inputs |
| Scientific allocation | Exact preserved 127/24 case bindings and draw plans, bound to the published freeze |

| Acquisition ledger | Fresh append-only source reservations, bound to the pilot contract |
| Trial allocation | Fresh irrevocable trial identity, bound to the pilot contract and current source session |

No document contains its own publication commit or raw hash. The acquisition revision comes from the independent public readback; embedding it inside the ledger would create a hash cycle. Pilot admission does not contain future ledger or trial-allocation hashes. The separately issued closure receipt binds their complete final hashes.

The caller must authenticate publication anchors and the complete external inventory. This pure validator does not fetch GitHub, inspect installed binaries, establish storage continuity or prove experimental results from hashes. Runtime authentication and current store/session checks are separate components. `VerifiedClosure` is immutable and cannot be directly constructed by an ordinary caller; only full validation issues it. This maintained-code capability boundary does not claim protection against arbitrary hostile Python introspection.

`receiver_telescope_adapter.from_telescope` also requires an independently trusted current epoch-millisecond `live_clock`. It checks integer, nondecreasing observations before and after every row-loader attempt against the authenticated session start, current-time anchor, deadline and fixed end of 9 October UTC. Equal millisecond observations are permitted. Expiry or clock regression closes the handoff and prevents later loads; an expiry detected after a callback does not admit its returned rows. The separate synthetic interface requires an explicit `fixture_clock` and grants no scientific authority. A bounded outer runtime must still interrupt a hung clock or loader, enforce memory/process/network limits and prevent repeated scientific dispatch; synchronous callback checks do not provide those guarantees.
