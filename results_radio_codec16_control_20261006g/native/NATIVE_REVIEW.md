# Codec16 G static native inventory

This inventory supplies exact file pins and a recursively inspected candidate ELF dependency graph for the restricted runtime control. It does not certify the complete effective runtime graph or authorize scientific execution.

The seeds are the 63 ELF files declared by E for NumPy 2.3.5, h5py 3.16.0 and hdf5plugin 7.1.0, the exact original C venv interpreter, and ten ordinary system ELF files mapped in E. All twelve installed hdf5plugin binaries are included, so the scope contains bitshuffle and is broader than a minimal bitshuffle test. E's old supervisor `exec_seal.so` is excluded: a new control supervisor requires a separate pin.

`build_native_inventory.py` uses a host Python process only for JSON, filesystem operations, hashing, copying and invoking `/usr/bin/readelf`. It never executes the inventoried interpreter, imports the installed packages, runs `ldd`, invokes the ELF loader, or launches any scientific/native target diagnostic. `readelf` parses ELF bytes as data. Each file is hashed, copied into `native/files/<sha256>` as a scratch review intermediate, independently hash-checked after copying, and rechecked for filesystem identity stability across byte reading and static inspection. These copies are excluded from G publication and allocation; they are not G scientific runtime clones. Each node instead records its absolute-path C archive member and verifies those retained bytes against the live exact input pin. `native/readelf/` retains raw static program-header and dynamic-table observations.

For every `DT_NEEDED` name and `PT_INTERP` path the graph records candidate files, the selected static lookup tier and the selected canonical path. Own-object RPATH/RUNPATH expand `$ORIGIN`; the declared runtime/system directories and E-observed name candidates form additional lookup tiers. Symlink spellings resolving to one ordinary file are deduplicated. Unresolved names, multiple ordinary candidates in the preferred nonempty tier, and unsupported path tokens are explicit exceptions.

The generated inventory has 74 retained ordinary ELF files, 293,051,163 bytes and 218 dependency/interpreter edges. The declared static lookup finds one candidate for each edge; no exception, E hash mismatch or E dynamic-table field mismatch was found. These are static observations within the declared model, not evidence that all runtime loading possibilities have been covered. All 74 retained files have exact E hash agreement.

Inherited RPATH context, environment search paths, `ld.so.cache` precedence, hwcaps alternatives, already-loaded namespace reuse, interposition, symbol/version compatibility and `dlopen` paths are not fully modeled. E maps are historical observations, not observations of G. Pure Python and other non-ELF source files are outside this inventory and need the separate source/input pins. After any G control launch, independently captured native maps should be compared against these path/hash pins and any unlisted ELF should be treated as a new observation requiring review.

No completeness certificate, runtime qualification, source closure qualification or telescope-data execution qualification is issued here. The actionable result is the retained input pins plus independently parsed native fields, suitable for a narrow control whose actual execution law and observed maps are reviewed separately.
