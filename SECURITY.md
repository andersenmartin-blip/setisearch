# Security policy

## Supported version

Security fixes are applied to the current `main` branch and the latest tagged
release. Historical milestone outputs remain immutable research records.

## Reporting a vulnerability

Please use **Security → Report a vulnerability** on the GitHub repository to
submit a private report. Include the affected file or workflow, the potential
impact, and a minimal reproduction when safe to do so.

If private vulnerability reporting is temporarily unavailable, open a minimal
public issue asking the maintainer to enable a private reporting channel. Do
not place credentials, personal information, exploit details, or unredacted
logs in a public issue.

Public scientific disagreements, reproducibility problems, and suspected data
or analysis errors are not security vulnerabilities and should be reported as
ordinary GitHub issues.
